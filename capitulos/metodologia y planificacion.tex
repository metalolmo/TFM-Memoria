\chapter{Metodología y Planificación}

En el desarrollo de este trabajo fue necesario definir una metodología clara que sirviera de guía a lo largo de todo el proceso. El proyecto presentaba una dificultad añadida frente a otros trabajos puramente software: la necesidad de establecer conectividad con routers Cisco en un entorno de simulación mediante GNS3. Este aspectó condicionó desde el inicio la planificaación, ya que sin resolver esta problemática no era posible avanzar hacia fases posteriores. Por este movito, la consecución de la conectividad se planteó como el primer objetivo fundamental dentro de la metodología adoptada.

Una vez superado este hito, el trabajo se organizó de manera secuencial. En primer lugar, se implementó el backend, encargado de gestionar la comunicación con los routers y el tratamiento de la información obtenida. Posteriormente, se desarrolló el frontend, con el propósito de representar los datos de manera visual e intuitiva. Todo el proceso se llevó a cabo siguiendo un enfoque iterativo, en el que cada avance era probado y validado antes de pasar al siguiente, lo que permitió corregir errores de forma temprana y ajustar la planificación conforme se identificaban nuevas necesidades.

\section{Metodología de trabajo}

Para el siguiente proyecto se optó por una metodología de carácter iterativo e incremental, adaptada a las necesidades concretas del trabajo. La elección de este enfoque respondió a la naturaleza experimental del sistema planteado, en el que era previsible encontrar dificultades técnicas relacionadas principalmente con la conectividad a los routers y la extracción de información en tiempo real. Adptar un modelo rígido de desarrollo (como el modelo en cascada) habría limitado la capacidad de reacción ante imprevistos, por lo que se consideró más adecuado trabajar con ciclos cortos de análisis, implementación y validación. Para la estructura de la metodología se siguió el diagrama de fases representado en la Figura~\ref{fig:fases},

    {\includegraphics[width=0.95\linewidth]{imagenes/image15.png}}
    \caption{Diagrama de fases}
    \label{fig:fases}

El proyecto se estructuró en fases principales, cada una de las cuales finalizaba con un resultado verificable antes de pasar a la siguiente. En primer lugar, se realizó el análisis de requisitos, en el que identificaron la funcionalidades necesarias (obtención d estadísticas de tráfico, estado de interfaces, uso de CPU, detección de errores, entre otras) y las limitaciones técnicas del entorno de trabajo. La segunda fase correspondió al diseño de la arquitectura, en la que se definió la división entre el backend y el frontend, así como la forma de interactuar con los routers a través de conexiones SSH.

A continuación, se llevó a cabo la fase de implementación, que se organizó de manera incremental. En esta etapa, la prioridad inicial fue conseguir la conectvidad estable con los routers y extraer información básica de la interfaces. Una vez validado este punto, se desarrollaron los módulos principales del backend con FastAPI, encargados de procesar y servir los datos del sistema. Posteriormente, se diseñó el frontend con Vue.js y Bootsrap, orientado a la visualización clara e interactiva de la información obtenida.

La metodología adoptada también completó un proceso de pruebas continuas. Cada módulo desarrollado se validaba en escenarios de red emulados en GNS3, lo que permitió detectar errores en fases tempranas y garantizar que los comopnentes eran funcionales antes de integrarlos con el resto del sistema. Además las revisiones periódicas con el tutor del proyecto facilitaron la reorientación de tareas cuando surgían dificultades, manteniendo el trabajo alineado con los objetivos planteados.



\section{Herramientas utilizadas}

El desarrollo del sistema requirió el uso de un conjunto variado de herramientas, tanto de software como de red, que facilitaron la implementación, las pruebas y la gestión del proyecto. La selección de estas herramientas no fue arbitraria, sino que respondió a las necesidades específicas del trabajo.

En primer lugar, se empleó GNS3 como entorno de simulación de red \citep{GNS3}. Esta herramienta permitió emular routers Cisco de manera flexible y reproducir escenarios de laboratorio realistas, lo que resultó fundamental para validar la conectividad y la extracción de información a través de SSH \citep{SSH}. GNS3 se encuentra ampliamente validado en el ámbito educativo y profesional, ya que facilita la integración de laboratorios virtuales y físicos en la formación en telecomunicaciones \citep{Kumar2015,Santos2021}. Gracias a GNS3, fue posible repetir pruebas sin depender de hardware físico, reduciendo costes y asegurando un entorno de experimentación controlado.

Para el desarrollo del backend se utilizó Python junto con el framework FastAPI \citep{FastAPI}, que ofreció un entorno ligero, modular y con soporte nativo para la creación de APIs REST. Esta elección permitió implementar de forma clara distintos endpoints para la obtención de información de los routers y la gestión de usuarios. La librería {Paramiko} se empleó como componente clave para establecer conexiones SSH con los dispositivos de red, lo que convirtió a esta combinación en el núcleo del sistema. Además, FastAPI ha sido reconocida en la literatura como una alternativa eficiente para aplicaciones web de alto rendimiento \citep{Tolo2022} e incluso en proyectos de monitorización integrados con Prometheus y Grafana \citep{Mwaura2023}.

El frontend se desarrolló con Vue.js \citep{Vue}, acompañado del framework visual Bootstrap \citep{Bootstrap} y de la librería Chart.js \citep{ChartJS,ChartJSmanual2024} para la representación gráfica de métricas en tiempo real. Esta combinación permitió construir una interfaz moderna, intuitiva y adaptable, en la que el usuario puede visualizar el estado del router, las estadísticas de tráfico y los errores detectados de forma clara. Asimismo, el archivo de configuración environment.json se incorporó para facilitar la personalización de parámetros como tiempos de refresco o colores de visualización sin necesidad de modificar el código.

En lo relativo a la gestión del proyecto se utilizó Git y GitHub como sistemas de control de versiones, lo que facilitó el mantenimiento de un registro ordenado de cambios, así como recuperar versiones anteriores en caso de error.

Finalmente, se destaca el uso de librerías adicionales que complementaron el sistema, como ReportLab para la generación automática de informes en PDF con los errores detectados, y smtplib para el envío de dichos informes por correo electrónico al usuario autenticado. Además, se integró el uso de JSON Web Tokens (JWT) como mecanismo de autenticación segura en el acceso a la plataforma \citep{JWT}.

\section{Planificación temporal}

La planificacion temporal del proyecto se organizó de acuerdo con un enfoque secuencial, en el que cada fase dependía directamente de la finalización de la anterior. Dada la complejidad inicial para establecer la conectividad con los routers en el entorno de simulación, los primeros meses (febrero-abril) se dedicaron integramente a resolver eta problemática. Durante este periodo se realizaron las configuraciones necesarias para garantizar la comunicación entre el emulador y el sistema anfitrión, así como la validación de los accesos mediante el protocolo SSH.

Una vez conseguida la conectividad, se dio inicio al desarrollo del backend (mayo-junio), centrado en la implementación de la lógica del sistema, la integración de librerías para conexiones seguras (Pramiko), la definición de los endpoints en FastAPI. Posteriormente, se abordó el desarrollo del forntend (junio-Julio), en el que se miplementó la interfaz de usuario utilizando Vue.js, Bootstrap y Chart.js, con especial atención a la visualización de me´tricas en tiempo real y a la personalización mediante un archivo enviroment.json. Para finalizar, se incorporó mecanismos de autenticación y generación de informes.

La fase final del proyecto (Julio) se dedicó a la validación del sistema en su conjunto, a través de pruebas de funcionamiento, simulaciones de errores y comprobación de alertas. En la Figura~\ref{fig:gantt} se presenta el diagrama de Gantt que resume esta planificación temporal y refleja los 
hitos más relevantes alcanzados a lo largo del proyecto.
